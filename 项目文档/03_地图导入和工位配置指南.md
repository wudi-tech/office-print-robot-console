# 地图导入和工位配置指南

> 公开归档说明：本文是部署与待集成步骤，不是整机验收记录。仓库包含 Web/PWA、演示 HTTP 服务、ROS2 HTTP 桥接和 USB 打印节点；调度器、Nav2/底盘驱动、真实地图与设备均需另行提供。桥接 API 可达只表示服务连接，CUPS 命令成功只表示打印请求已提交，均不证明导航就绪或纸张已输出。所有工位/地图坐标与用户数据为示例，不能直接用于实机。当前验证见 [验证记录](../docs/VALIDATION.md)。

目标：把小车建好的真实地图导入系统，并在地图上划分工位，让网页选择的工位能对应到 ROS2 真实导航坐标。

请记住一句话：

```text
地图给 Nav2 导航用。
工位配置文件负责把“工位编号”转换成“真实 ROS2 坐标”。
```

不要把工位写死在地图图片里。工位应该写在 JSON 配置文件中。

## 1. 先理解两个坐标系

本项目同时用两个坐标系。

### UI 坐标

用于网页显示。

```json
"ui": { "x": 466, "y": 330 }
```

它表示某个工位圆点在网页地图上的位置。

### ROS 坐标

用于小车真实导航。

```json
"ros": { "x": 4.1, "y": 0.1, "yaw": 1.57 }
```

它表示 Nav2 地图 `map` 坐标系中的目标点。

字段解释：

```text
x    地图中的横向位置，单位通常是米
y    地图中的纵向位置，单位通常是米
yaw  小车到达工位后的朝向，单位是弧度
```

常用 yaw：

```text
0       面向 x 正方向
1.57    约等于 90 度
3.14    约等于 180 度
-1.57   约等于 -90 度
```

## 2. 保存小车建好的地图

小车完成 SLAM 建图后，在 RDK X5 上执行：

```bash
mkdir -p /opt/office-print-robot-console/maps
ros2 run nav2_map_server map_saver_cli -f /opt/office-print-robot-console/maps/office_3f
```

成功后会得到：

```text
/opt/office-print-robot-console/maps/office_3f.yaml
/opt/office-print-robot-console/maps/office_3f.pgm
```

Nav2 官方提供 `map_saver_cli` 用于保存地图。参考：

```text
https://docs.nav2.org/configuration/packages/map_server/configuring-map-saver.html
```

## 3. 检查地图文件

查看文件：

```bash
ls -lh /opt/office-print-robot-console/maps
```

打开 YAML：

```bash
cat /opt/office-print-robot-console/maps/office_3f.yaml
```

通常会看到类似内容：

```yaml
image: office_3f.pgm
mode: trinary
resolution: 0.05
origin: [-10.0, -10.0, 0.0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.25
```

其中：

```text
resolution  每个像素代表多少米
origin      图片左下角在 ROS map 坐标系中的位置
image       对应的地图图片文件
```

## 4. 让 Nav2 使用真实地图

启动 Nav2 时指定地图：

```bash
ros2 launch nav2_bringup bringup_launch.py map:=/opt/office-print-robot-console/maps/office_3f.yaml
```

如果你有自己的 launch 文件，就把 map 参数改成：

```text
/opt/office-print-robot-console/maps/office_3f.yaml
```

## 5. 把地图显示到网页

网页一般不能直接优雅显示 `.pgm`，建议转成 `.png`。

如果 RDK X5 安装了 ImageMagick：

```bash
sudo apt install -y imagemagick
convert /opt/office-print-robot-console/maps/office_3f.pgm /opt/office-print-robot-console/web/maps/office_3f.png
```

如果没有 ImageMagick，也可以把 `office_3f.pgm` 复制到电脑，用图片工具转成 PNG，再放回：

```text
web/maps/office_3f.png
```

然后修改：

```text
web/config/office_3f.json
```

找到：

```json
"image": ""
```

改成：

```json
"image": "./maps/office_3f.png"
```

刷新网页后，地图区域就会显示真实地图图片。

## 6. 调整地图图片显示范围

如果真实地图显示太大、太小或偏移，修改：

```json
"imageBounds": {
  "x": 24,
  "y": 34,
  "width": 852,
  "height": 452
}
```

含义：

```text
x       图片左上角在网页 SVG 中的横坐标
y       图片左上角在网页 SVG 中的纵坐标
width   图片显示宽度
height  图片显示高度
```

初学者可以按这个方法调：

```text
图片太靠左：增大 x
图片太靠右：减小 x
图片太靠上：增大 y
图片太靠下：减小 y
图片太大：减小 width 和 height
图片太小：增大 width 和 height
```

## 7. 在网页上放置工位点

工位点也在：

```text
web/config/office_3f.json
```

每个工位类似：

```json
{
  "id": "C-05",
  "label": "产品 C-05",
  "type": "desk",
  "marker": "C",
  "selectable": true,
  "ui": { "x": 466, "y": 330 },
  "ros": { "x": 4.1, "y": 0.1, "yaw": 1.57 }
}
```

先只调整 `ui`：

```json
"ui": { "x": 466, "y": 330 }
```

刷新网页，看圆点是否落在对应工位上。

如果位置不对，就慢慢改 `x` 和 `y`。

```text
圆点太靠左：增大 ui.x
圆点太靠右：减小 ui.x
圆点太靠上：增大 ui.y
圆点太靠下：减小 ui.y
```

注意：网页 SVG 的 y 轴是向下增大的，这和数学坐标不一样。

## 8. 记录真实 ROS 工位坐标

这是最关键的一步。

### 8.1 启动定位

先启动你的地图和定位系统，例如 Nav2 + AMCL。确认小车在 RViz 中定位正常。

### 8.2 把小车开到工位前

把小车移动到工位前合适的位置：

```text
不要贴太近桌子
留出小车转弯空间
让小车朝向方便取放文件
```

### 8.3 读取 /amcl_pose

在 RDK X5 上执行：

```bash
ros2 topic echo /amcl_pose
```

找到：

```text
pose:
  pose:
    position:
      x: 4.1
      y: 0.1
    orientation:
      z: 0.707
      w: 0.707
```

记录 `position.x` 和 `position.y`。

### 8.4 获取 yaw

如果你暂时不会四元数转换，可以先用常见方向：

```text
朝东：0
朝北：1.57
朝西：3.14
朝南：-1.57
```

后续要更精确，可以用脚本把四元数转成 yaw。

Python 示例：

```python
import math

z = 0.707
w = 0.707
yaw = math.atan2(2.0 * w * z, 1.0 - 2.0 * z * z)
print(yaw)
```

## 9. 填写真实 ROS 坐标

修改两个配置文件，保持一致：

```text
web/config/office_3f.json
ros2_ws/src/print_robot_bridge/config/office_3f.json
```

把工位的 `ros` 改成真实测量值：

```json
{
  "id": "C-05",
  "label": "产品 C-05",
  "ui": { "x": 466, "y": 330 },
  "ros": { "x": 4.1, "y": 0.1, "yaw": 1.57 }
}
```

如果你使用 RDK X5 外部配置：

```bash
ros2 launch print_robot_bridge bridge.launch.py \
  stations_config:=/opt/office-print-robot-console/config/office_3f.json
```

那就只需要维护外部这份配置。

## 10. 测试工位配置是否生效

启动桥接节点：

```bash
ros2 launch print_robot_bridge bridge.launch.py host:=0.0.0.0 port:=8080
```

查看配置接口：

```bash
curl http://127.0.0.1:8080/api/floor-config
```

你应该能看到 `stations` 和每个工位的 `ros` 坐标。

然后监听任务：

```bash
ros2 topic echo /print_robot/jobs/request
```

在网页提交目标工位为 `C-05` 的任务。

你应该看到类似：

```json
{
  "targetStation": "C-05",
  "targetLabel": "产品 C-05",
  "targetPose": {
    "x": 4.1,
    "y": 0.1,
    "yaw": 1.57
  }
}
```

这说明：

```text
网页选择工位 C-05
        ↓
RDK X5 查配置
        ↓
任务里带上真实 targetPose
        ↓
调度节点可以让 Nav2 去这个点
```

## 11. 新增一个工位

在 `stations` 数组里复制一个旧工位，然后改：

```json
{
  "id": "A-02",
  "label": "研发 A-02",
  "type": "desk",
  "marker": "A2",
  "selectable": true,
  "ui": { "x": 220, "y": 151 },
  "ros": { "x": 1.8, "y": 2.4, "yaw": 1.57 }
}
```

注意：

```text
id 不能重复
selectable 为 true 才会出现在网页下拉框
type 为 dock 一般不让用户选择
```

## 12. 删除一个工位

直接从 `stations` 数组中删除对应对象即可。

删除前确认：

```text
没有任务还在使用这个工位编号
网页和 RDK X5 使用的配置都同步删除
```

## 13. 修改充电点

打印机已经安装在小车上，不再需要在地图里设置固定“打印区”工位。地图里通常只需要保留充电点：

```json
"type": "dock"
```

通常：

```json
"selectable": false
```

因为用户提交配送任务时不应该把“充电点”当作收件工位。

## 14. 常见问题

### 网页地图不显示 PNG

检查：

```text
图片路径是否是 ./maps/office_3f.png
图片是否真的放在 web/maps/office_3f.png
npm start 是否已经重启或浏览器是否强制刷新
```

强制刷新：

```text
Windows: Ctrl + F5
手机: 关闭页面后重新打开
```

### 网页工位点和真实地图对不上

先调 `ui`，不要动 `ros`。

```text
ui 只影响网页显示
ros 影响小车导航
```

### 小车导航到错误位置

重点检查：

```text
是否改了 ros 坐标
网页和 RDK X5 的配置是否一致
targetStation 是否和配置里的 id 一致
Nav2 是否加载了同一张 office_3f.yaml 地图
```

### 同一个工位网页显示对，但小车去错

说明 `ui` 对了，`ros` 错了。重新把小车开到该工位前，读取 `/amcl_pose`，再更新 `ros`。

### 小车朝向不对

只改 `yaw`：

```text
0
1.57
3.14
-1.57
```

逐个试，找到最适合取放文件的朝向。
